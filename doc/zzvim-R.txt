============================================================================
1. INTRODUCTION                                            *zzvim-r-introduction*

zzvim-R provides integration between Vim and R, enabling code execution and
workspace management from within the editor. The plugin allows users to send
commands to an R terminal, navigate R Markdown chunks, and inspect R objects
directly from Vim. The plugin supports R script files (.R) as well as R
Markdown (.rmd) and Quarto (.qmd) documents.

Key capabilities:
- Code execution with pattern-based detection
- Multi-terminal session management with buffer-specific sessions
- R Markdown/Quarto chunk navigation
- Object inspection functions
- Non-interactive code submission
- Pattern recognition for R language constructs

============================================================================
2. ABSTRACT                                                  *zzvim-r-abstract*

zzvim-R enables R programming workflows within the Vim text editor. The plugin
supports interactive code execution, multi-file project management, and R
Markdown document editing. It is designed for users who prefer Vim for code
editing and require R integration without leaving the editor.

3. REQUIREMENTS                                            *zzvim-r-requirements*

Requirements:
    * Vim 8.0 or newer with +terminal feature
    * R installed and accessible in PATH

System Specifications:
- Vim: Version 8.0 or newer (terminal feature required)
- R: Version 3.6 or higher recommended
- Operating System: Linux, macOS, Windows
- RAM: 512MB minimum; 2GB+ recommended for large datasets

Dependencies:
- Vim terminal emulation for R session management
- Vim job control for process communication
- Temporary file handling for code submission

System Compatibility Verification: >
    :echo has('terminal')          " Verify terminal support
    :echo v:version               " Check Vim version compatibility
    :echo executable('R')         " Validate R installation
<

4. INSTALLATION                                          *zzvim-r-installation*

Package Manager Integration                    *zzvim-r-installation-managers*

Vim-Plug Installation Protocol: >
    " Add to your ~/.vimrc or init.vim
    Plug 'your-username/zzvim-r.vim'
    
    " Execute installation command
    :PlugInstall
<

Vundle Configuration Framework: >
    " Vundle-based installation in ~/.vimrc
    Plugin 'your-username/zzvim-r.vim'
    
    " Execute within Vim
    :PluginInstall
<

Pathogen Compatibility: >
    # Manual pathogen installation
    cd ~/.vim/bundle
    git clone https://github.com/your-username/zzvim-r.vim.git
<

Manual Installation Procedures                      *zzvim-r-manual-installation*

For environments requiring manual plugin management: >
    # Create plugin directory structure
    mkdir -p ~/.vim/pack/plugins/start/
    
    # Clone repository to plugin location
    git clone https://github.com/your-username/zzvim-r.vim.git \
      ~/.vim/pack/plugins/start/zzvim-r.vim
    
    # Generate help tags
    vim -c 'helptags ~/.vim/pack/plugins/start/zzvim-r.vim/doc' -c 'quit'
<

5. CONFIGURATION                                          *zzvim-r-configuration*

The following variables can be set in your vimrc to customize the plugin.
The zzvim-R plugin implements a sophisticated configuration system that
enables granular control over functionality and behavior following Vim's
standard global variable convention.

Core Configuration Variables                    *zzvim-r-configuration-core*

                                                    *g:zzvim_r_default_terminal*
g:zzvim_r_default_terminal    Sets the default terminal name for R sessions.
                             Default: 'R'
                             Example: >
                             let g:zzvim_r_default_terminal = 'R-4.1'
<
                                                      *g:zzvim_r_terminal_width*
g:zzvim_r_terminal_width     Terminal window width in columns for vertical splits.
                             Default: 100
                             Example: >
                             let g:zzvim_r_terminal_width = 120
<
                                                     *g:zzvim_r_terminal_height*
g:zzvim_r_terminal_height    Terminal window height in lines for horizontal
                             splits.
                             Default: 15
                             Example: >
                             let g:zzvim_r_terminal_height = 20
<
                                                          *g:zzvim_r_command*
g:zzvim_r_command            R startup command with parameters.
                             Default: 'R --no-save --quiet'
                             Example: >
                             let g:zzvim_r_command = 'R --max-mem-size=8G'
<
                                                    *g:zzvim_r_disable_mappings*
g:zzvim_r_disable_mappings   If set to 1, disables all default key mappings.
                             Default: 0
                             Example: >
                             let g:zzvim_r_disable_mappings = 1
<
                                                              *g:zzvim_r_pipe*
g:zzvim_r_pipe               Pipe operator appended by <localleader>| and
                             :RAddPipe.
                             Default: '|>' (native pipe, R >= 4.1)
                             Example: >
                             let g:zzvim_r_pipe = '%>%'
<
                             To move code submission off <CR>, map
                             <Plug>(zzvim-r-send-smart) yourself (see
                             |zzvim-r-mappings-plug|). The former
                             g:zzvim_r_map_submit option was documented but
                             never read, and was removed in v0.10.2.
                                                      *g:zzvim_r_chunk_start*
g:zzvim_r_chunk_start        R Markdown chunk start pattern (regex).
                             Default: '^```{'
                             Example: >
                             let g:zzvim_r_chunk_start = '^```{r.*}'
<
                                                        *g:zzvim_r_chunk_end*
g:zzvim_r_chunk_end          R Markdown chunk end pattern (regex).
                             Default: '^```$'
                             Example: >
                             let g:zzvim_r_chunk_end = '^```\s*$'
<
                                                            *g:zzvim_r_debug*
g:zzvim_r_debug              Debug logging level (0=off, 1=basic, 2=verbose).
                             Default: 0
                             Example: >
                             let g:zzvim_r_debug = 1
<

6. COMMANDS                                                    *zzvim-r-commands*

The plugin provides the following commands. This command architecture enables
script automation, custom workflow development, and integration with external
tools.

Core Operational Commands                            *zzvim-r-commands-core*

Terminal Launch Commands:                          *zzvim-r-commands-terminal*

:ROpenTerminal                                                *:ROpenTerminal*
    Establish buffer-specific R computational environment.
    Auto-detects zzcollab workspace and uses Docker if present.

:RDockerTerminal                                            *:RDockerTerminal*
    Launch R in Docker container via `make r`.
    Requires Makefile with `r:` target configured for Docker.

:RTerminalLocal                                              *:RTerminalLocal*
    Launch R on host with renv (normal startup).
    Sources .Rprofile for renv activation.

:RTerminalVanilla                                          *:RTerminalVanilla*
    Launch R on host without renv (vanilla mode).
    Uses `R --vanilla` which skips .Rprofile and .Renviron.
    Useful for debugging or system R without project isolation.

:RDockerTerminalForce                                  *:RDockerTerminalForce*
    Force-associate current buffer with existing Docker terminal.
    Use when terminal was created manually outside zzvim-R.

Code Submission Commands:                        *zzvim-r-commands-submission*

:RSendLine                                                        *:RSendLine*
    Submit current line with context awareness (silent execution).

:RSendFunction                                                *:RSendFunction*
    Submit complete function definition with enhanced pattern recognition.

:RSendSmart                                                      *:RSendSmart*
    Intelligent pattern-based code submission with brace/parenthesis matching.

:RSendSelection                                              *:RSendSelection*
    Submit visual selection boundaries (silent execution).

:RNextChunk                                                      *:RNextChunk*
    Move cursor to the next R Markdown chunk.
    Advance to subsequent literate programming chunk.

:RPrevChunk                                                      *:RPrevChunk*
    Move cursor to the previous R Markdown chunk.
    Navigate to preceding literate programming chunk.

:RSelectChunk                                                    *:RSelectChunk*

:RSendChunk                                                      *:RSendChunk*
    Execute current chunk with dependencies (buffer-specific terminal).

:RSendPreviousChunks                                    *:RSendPreviousChunks*
    Execute all preceding chunks sequentially (buffer-specific terminal).

:RAddPipe                                                          *:RAddPipe*
    Append the pipe (|g:zzvim_r_pipe|, default |>) to the current line

7. MAPPINGS                                                    *zzvim-r-mappings*

The following mappings are available when g:zzvim_r_disable_mappings is 0.
Every action also has a named |zzvim-r-mappings-plug| target, so any single
key below can be remapped without disabling the rest; see
|zzvim-r-mappings-custom|.

                                                   *zzvim-r-mappings-v0.10.0*
v0.10.0 regroups these keys: 'r' and 's' are now pure prefixes (no bare
<localleader>r or <localleader>s command), object inspection moved under a
new 'o' prefix, HUD windows moved under a new 'u' prefix, and plot
previous/next moved onto '[' and ']' to match Vim's own bracket-pair
convention. See |zzvim-r-mappings-migration| for the full old-to-new table
if you have muscle memory from an earlier version.

Primary Interaction Layer (Normal Mode)           *zzvim-r-mappings-primary*

Normal Mode:
    <CR>              Submit current line to R (smart context-aware dispatch)

R Terminal Launch:                                *zzvim-r-mappings-terminal*
    <localleader>rd   Container R (via make r, with renv)
    <localleader>rl   Host R with renv (normal startup, sources .Rprofile)
    <localleader>rn   Host R without renv (vanilla mode, skips .Rprofile)
    <localleader>rf   Force a new Docker terminal
    <localleader>w    Open R terminal in new vertical split window
    <localleader>W    Open R terminal in new horizontal split window
    <localleader>|    Append pipe (|> by default) and open a new line
    <localleader>j    Move to next chunk (forward chunk traversal)
    <localleader>k    Move to previous chunk (backward chunk traversal)
    ]]                Move to next chunk (operator- and count-composable;
                      alias of <localleader>j; works as a motion, e.g. d]])
    [[                Move to previous chunk (alias of <localleader>k)
    <localleader>sc   Select and submit current chunk (execute chunk)
    <localleader>sp   Submit all previous chunks (cumulative execution)
    <localleader>rk   Render to default format (respects YAML front matter)
    <localleader>rp   Render to HTML and open in browser
    <localleader>rv   Render to PDF (pdf_document)
    <localleader>nb   Insert R chunk below (rmd/quarto only)
    <localleader>na   Insert R chunk above (rmd/quarto only)
    <localleader>T    Render zztable1 blueprint under cursor via Typst
    <localleader>'    Show workspace overview (object browser)
    <localleader>q    Send 'Q' to R terminal (graceful session termination)
    <localleader>c    Send Ctrl-C to R terminal (interrupt signal)

Object Inspection Layer (Analytical Functions)   *zzvim-r-mappings-inspection*

R Function Shortcuts, all under the 'o' prefix. Each also has a visual-mode
counterpart on the same key, which inspects the visual selection (e.g.
df$x) rather than the word under the cursor:
    <localleader>od   Run dim() (dimensional analysis)
    <localleader>oh   Run head() (data preview)
    <localleader>ot   Run tail() (terminal preview)
    <localleader>os   Run str() (structural analysis)
    <localleader>op   Run print() (content display)
    <localleader>on   Run names() (attribute inspection)
    <localleader>ol   Run length() (size determination)
    <localleader>og   Run glimpse() (tibble inspection)
    <localleader>ob   Run dt() (data.table display)
    <localleader>ou   Run summary()
    <localleader>i    Intelligent object inspection (adaptive display)

Enhanced Object Inspection                       *zzvim-r-mappings-enhanced*

Data Viewer (Enhanced RAction):
    <localleader>uv   Open RStudio-style data viewer for object under cursor

HUD Functions (Workspace Overview)               *zzvim-r-mappings-hud*

Individual HUD Displays, all under the 'u' prefix:
    <localleader>um   Memory Usage HUD - show object memory consumption
    <localleader>ud   Data Frames HUD - overview of all data frames
    <localleader>up   Package Status HUD - display loaded packages
    <localleader>ue   Environment Variables HUD - system environment
    <localleader>uo   R Options HUD - current R session options

Unified HUD Dashboard                            *zzvim-r-mappings-dashboard*

Complete Workspace Overview:
    <localleader>uu   HUD Dashboard - open all 6 HUD displays in tabs
                      Creates tabbed workspace overview for situational awareness
                      Use gt/gT to navigate tabs, :q to close, <localleader>uu to refresh

Plots                                                *zzvim-r-mappings-plots*

    <localleader>pp   Open Plot HUD
    <localleader>[    Previous plot (no HUD)
    <localleader>]    Next plot (no HUD)
    <localleader>pz   Zoom current plot (open vector PDF)
    <localleader>ph   Plot history list
    <localleader>ps   Save current plot

Explicit Send Mappings                            *zzvim-r-mappings-explicit*

Generalized Send Functions (Advanced), under the 's' prefix:
    <localleader>sf   Force send function block (override smart detection)
    <localleader>ss   Force send current line only (line-by-line evaluation)
    <localleader>sc   Submit current chunk (same key as the chunk-submit
                      mapping above; it is the 's'-prefix member of this
                      group as well as the chunk-navigation group)
    <localleader>sp   Send all previous chunks

Visual Selection Interface                         *zzvim-r-mappings-visual*

Visual Mode:
    <CR>              Submit visual selection (user-defined boundaries)
    <localleader>oX   Inspect visual selection with R function X, where X
                      is any letter from the object-inspection group above
                      (d, h, t, s, p, n, l, g, b, u)

                                                     *zzvim-r-mappings-plug*
<Plug> Mapping Targets (v0.10.0)

Every action bound by default (section above) has a named <Plug> target,
defined once at script load time regardless of filetype, so it exists to
remap against even before a buffer's FileType autocommand has fired. To
change a single key without touching any other default, remap the
<Plug> target instead of disabling g:zzvim_r_disable_mappings: >
    " Change only the chunk-submit key, in an r/rmd/quarto ftplugin or
    " autocmd FileType block; leave every other default as-is.
    nmap <buffer> <LocalLeader>X <Plug>(zzvim-r-chunk-submit)
<
The plugin checks hasmapto() before applying its own default for a given
<Plug> target, so once you have mapped it yourself (as above), the
plugin's own default key for that same action is not also applied.

<Plug> names, grouped the same way as the mapping tables above:
    <Plug>(zzvim-r-terminal-docker)      <Plug>(zzvim-r-terminal-local)
    <Plug>(zzvim-r-terminal-vanilla)     <Plug>(zzvim-r-terminal-docker-new)
    <Plug>(zzvim-r-split-vertical)       <Plug>(zzvim-r-split-horizontal)
    <Plug>(zzvim-r-send-selection)       <Plug>(zzvim-r-send-smart)
    <Plug>(zzvim-r-send-smart-comments)  <Plug>(zzvim-r-pipe-newline)
    <Plug>(zzvim-r-send-line)            <Plug>(zzvim-r-send-function)
    <Plug>(zzvim-r-send-prevchunks)      <Plug>(zzvim-r-chunk-next)
    <Plug>(zzvim-r-chunk-prev)           <Plug>(zzvim-r-chunk-submit)
    <Plug>(zzvim-r-ctrl-q)               <Plug>(zzvim-r-ctrl-c)
    <Plug>(zzvim-r-obj-dim/head/tail/str/print/names/length/glimpse/dt/summary)
    <Plug>(zzvim-r-objx-dim/head/tail/str/print/names/length/glimpse/dt/summary)
    (the objx- group is the visual-mode, selection-based counterpart)
    <Plug>(zzvim-r-workspace)            <Plug>(zzvim-r-inspect)
    <Plug>(zzvim-r-hud-memory/dataframe/package/environment/options)
    <Plug>(zzvim-r-viewer)               <Plug>(zzvim-r-hud-dashboard)
    <Plug>(zzvim-r-plot-hud/zoom/prev/next/history/save)

    <Plug>(zzvim-r-render-preview/knit/pdf)

                                                 *zzvim-r-mappings-nomixedcase*
No default key mixes upper- and lower-case letters in the same
sequence, since that forces a shift key mid-sequence and is easy to
mistype. <localleader>rD, <localleader>oS, and <localleader>ci/cI (an
earlier cut of v0.10.0 briefly had these) are now <localleader>rf,
<localleader>ou, and <localleader>nb/na respectively; see the
migration table below. The nb/na rename also fixed an unrelated
defect: <localleader>c (Ctrl-C) is a complete command active in every
one of r/rmd/quarto, so ci/cI's 'c' prefix collided with it in
rmd/quarto buffers specifically.

                                                *zzvim-r-mappings-migration*
Migration from 0.9.x

Old key -> new key, for every key that moved or was removed in v0.10.0,
v0.10.1, or v0.10.2:
    <localleader>o    -> <localleader>|   (v0.10.2: o was both a command
                                           and the prefix of the o?
                                           object keys; the pipe is now
                                           |> by default, see
                                           |g:zzvim_r_pipe|)
    <localleader>0    -> <localleader>uu  (v0.10.2: joins the u HUD group)
    <localleader>P    -> <localleader>pp  (v0.10.2: joins the p plot group)
    <localleader>r    -> <localleader>rd
    ZR                -> <localleader>rd  (ZR itself removed; exact
                                           duplicate, defect 13)
    <localleader>rr   -> <localleader>rl
    <localleader>rh   -> <localleader>rn
    <localleader>R    -> <localleader>rl  (<localleader>R itself removed;
                                           exact duplicate)
    <localleader>D    -> <localleader>rf  (v0.10.0 briefly used rD;
                                           see |zzvim-r-mappings-nomixedcase|)
    <localleader>ci   -> <localleader>nb  (v0.10.0 only; see above)
    <localleader>cI   -> <localleader>na  (v0.10.0 only; see above)

12. TROUBLESHOOTING                                     *zzvim-r-troubleshooting*

Common issues and solutions:

No R terminal available~
Make sure you have started an R terminal session before trying to send commands.
Use :ROpenTerminal to create a buffer-specific R session.

Commands not being sent to R~
Verify that:
    * Vim was compiled with terminal support (:echo has('terminal'))
    * R is properly installed and in your PATH (:echo executable('R'))
    * There is an active R terminal session (:RShowTerminal)

Multiple terminals~
If multiple terminal sessions are open, the plugin will prompt you to choose
which terminal to send commands to. Use :RListTerminals to see all associations.

13. DESIGN PHILOSOPHY                                          *zzvim-r-design*

This section records design decisions whose rationale is not obvious
from the code. It is intended for users who hit a rough edge and want
to understand why the plugin works the way it does.

Plot display: wrappers, not S3 overrides            *zzvim-r-design-plots*

zzvim-R exposes plot display via explicit R-side wrapper functions
(`show_plot()`, `show_table()`, and the convenience alias `show()`)
rather than overriding `print.ggplot` and friends as S3 methods.
This is a deliberate choice. The wrapper approach was adopted after
the override approach was implemented, tested, and found unsound.

The override approach attempts:
>
    print.ggplot <- function(x, ...) {
      .create_plot_device()
      original_print_ggplot(x, ...)
      dev.off()
      invisible(x)
    }
<
The intent is for `p <- ggplot(...) ; p` to display automatically.
This intent is not realisable safely. The problems are:

1. Initialization timing.

   When `.Rprofile` runs, `ggplot2` is not yet loaded, so
   `utils::getS3method('print', 'ggplot')` errors. Deferring with
   `setHook(packageEvent('ggplot2', 'attach'), ...)` introduces silent
   failures whose timing depends on R's package-load sequence rather
   than on user intent.

2. Namespace and load-order conflicts.

   Multiple packages compete for the same S3 method. The override that
   wins is the one assigned last, which is not stable across user
   environments. Users who define their own `print.ggplot` lose their
   customization without warning.

3. Graphics device hazards.

   The override forcibly opens and closes a device on every print.
   Nested printing (`sapply(plots, print)`), pre-existing device state
   (`png('out.png'); plot(x); dev.off()` followed by a ggplot), and
   errors mid-render all leave the device in inconsistent states.

4. Context coupling.

   `print()` is called from interactive consoles, from RStudio, from
   Rmd / qmd rendering, from Shiny apps, from `testthat`. An override
   cannot distinguish "user wants this displayed in their terminal"
   from "knitr is rendering the code chunk." The result is plots
   appearing where they should not, and tests failing on
   `expect_silent()`.

5. Base R has no S3 method to override.

   `plot(1:10)` returns nothing and triggers display through the
   active device, not through `print`. Replicating the behavior for
   base R requires shadowing `plot()` itself, which breaks
   introspection and is hostile to debuggers.

6. Errors disappear inside the dispatch.

   When something goes wrong inside an overridden `print` method, the
   user sees a bare warning out of context. Wrappers report errors
   from a named function the user invoked deliberately.

The wrapper approach (`show_plot(expr, .name = NULL)`) sidesteps all
six issues:

- It is a function, so it works the moment it is defined; no hook,
  no late-binding, no package-load ordering.
- It does not collide with anyone's `print` method.
- It owns the graphics device for the duration of one call and
  releases it deterministically.
- It is opt-in: code that does not call `show_plot()` is unaffected.
  Tests, Shiny apps, and Rmd rendering see no change in behavior.
- It works identically for base R plots and ggplot2 objects, with no
  function shadowing.
- It is discoverable: `?show_plot` returns help, error messages name
  the function, and stack traces remain readable.

The cost is that the user types `show_plot(...)` (or the shorter
`show(...)`) instead of letting auto-print do the work. In exchange
the system is robust to package load order, leaves third-party
print methods alone, and behaves the same in interactive and
non-interactive contexts.
